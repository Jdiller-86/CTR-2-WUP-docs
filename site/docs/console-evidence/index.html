    Console evidence review¶

    October 13: launch audio, GX transfers and compiled PICA draws¶

    The new private ZIP contains three full traces and two independent 4 KiB result files. Audio Check 0.20.0 records both launch-music silence and the native tone as PASS in its full trace; its separate result file was not included. GX Transfers 0.20.0 and Guest Draws 0.23.0 each record both guide steps PASS in matching result and trace files, with no failed or skipped steps. All three traces reach main_return; the user separately confirms no launch music and correct exit. This is scoped hardware evidence, not full milestone acceptance.

    Diagnostic Reviewed physical evidence Timing and limits
    Audio Check 0.20.0 Silence prompt and native tone on both outputs PASS; five tone requests; clean shutdown No guest DSP/audio claim; standalone result TXT absent from this upload
    GX Transfers 0.20.0 Original guest PASS/exit, 17 GX operations, four paired presentations, zero fallback/fault Final transfer presentation at 6,882 ms; mean diagnostic host frame 145,948 us
    Guest Draws 0.23.0 Own PICA draw PASS/exit, four triangles, 97,200 fragments, 36 shader steps, zero fallback/fault; user confirms pictures Rendered second presentation at 57,330 ms; session 70,021 ms; mean host frame 153,189 us

    The physical draw run executed 17,457,061 instructions. The host reference count is 17,420,794; they are different runs, not an exact instruction-count match. The user estimates roughly two minutes before the draw picture appeared. The trace's first presentation at 1,235 ms is the startup framebuffer, not the rendered scene. These aggregate timings include diagnostic overhead and do not measure a game frame rate or isolate CPU rasterization, scaling, GPU waits or SD publication costs.

    The visual prompt accepted R at 10,221 ms, before the drawn second presentation. Its guide PASS alone therefore cannot prove the final triangle picture was confirmed at the right time. The user's separate confirmation and the later guest's own target/readback PASS remain evidence. A focused follow-up must gate the visual answer on the drawn presentation, measure individual phases and review the fixed 50,000-instruction-per-refresh budget. No audio, Save or RomFS repeat is requested solely for this evidence update.

    The user is available with Windows 11, an SD reader and current mainstream Wii U firmware/Aroma; exact versions were not supplied. Raw files and their SHA-256 receipt remain in ignored private storage. Full lifecycle/recovery, installed WUP, guest audio, broader graphics and useful game performance remain open.

    Five completed named result files were reviewed from the latest private ZIP. The user confirms correct screens and normal Minus return. All apps continued playing Wii U launch music; that remains an open audio defect. Raw uploads, snapshots and receipts stay in ignored private storage.

    Test Purpose Reviewed result

    Embedded RomFS 0.14.6 Read nested/Unicode assets and reject writes One step PASS in each of two launches
    SD Asset Files 0.16.0 Read a tiny original asset blob from SD One step PASS
    GX Transfers 0.18.0 Copy/fill/transfer pixels and finalize no-draw PICA configuration Two steps PASS; 17 GX operations, 11 configuration writes

    Every new result reports an exited guest, zero interpreter fallback and no guest fault. The 88-byte snapshot has a valid CRC and both original visit-2 records. The follow-up Save trace identifies 0.14.6, loads the existing snapshot in its first guest session, records RELOAD PASS, completes both steps without failures or skips and states Fresh-launch save reload confirmed: YES. Cleanup reaches main_return; Menu return also has the user's separate confirmation. No new Save or RomFS run is requested.

    The ZIP retains older failed Save 0.14.5 traces and an empty Guarded file, separate from current successes. A nonempty Guarded 0.14.5 trace records all eight guide steps PASS. This does not identify the cause of older failures or establish universal freeze recovery.

    Next: the short launch-audio check. Exact platform versions, Home/APT routes, installed WUP acceptance, actual PICA draws and commercial title requirements remain open. Scoped successes do not accept a full milestone.

    Historical guarded 0.14.3 report¶

    The uploaded report identifies compiled-guarded 0.14.3. Its complete shutdown and guide results match the user's first, delayed-green run. It does not capture the second launch that froze; the user confirms that launch saved no partial file.

    Observation Recorded evidence
    Initial picture User confirmed PASS
    A input One press; held A reached the standard HID publication
    Button-response guide User marked FAIL; this remains a failure
    Guide completion Cancelled during touch step: 1 passed, 1 failed, 6 unfinished
    Embedded checks All nine returned PASS
    Post-input checkpoints 64 complete ordered frames, including two pixel-decode pairs
    Guest execution 6,029,629 instructions, no interpreter fallback or guest fault
    Display Five matched presentations; no reported device failure or dropped IRQ
    Host-frame timing Average 285,194 us, range 261,544–326,732 us; about 3.5 frames/s
    Guarded AOT Maximum call depth 2; 24 recorded unwinds
    Shutdown Resource cleanup, RELEASE_FOREGROUND, EXITING, ProcUI/WHB shutdown and main_return checkpoints

    The user separately confirms launcher return. A main_return marker alone does not prove that the Wii U Menu finished loading. The log has three IPC request failures, so zero guest faults must not be described as zero service failures. Frame-boundary stack headroom is not a measurement at the deepest native call.

    The long host-frame time supports investigating response delay. This version does not log decoded frame colors or A-to-green latency, so the exact delay and green-frame timing cannot be derived from these counters. Continued execution in this run cannot identify the cause of an intermittent failure on another run.

    v0.14.5 adds checked file sync/close and mounted-volume sync before continuing past critical checkpoints. Desktop process-termination tests verify scoped recovery, and SDK builds verify the actual imports. SD controller durability, FSA behavior during a console freeze, and the original freeze remain unverified. That earlier retest request is superseded by the latest feedback and v0.14.6 save/result-file round above.
