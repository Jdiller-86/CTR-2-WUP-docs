    Project completion assessment¶

    Updated October 13, 2026, against version 0.20.0 and the product plan.

    The live Project owns current task states, waiting resources and reviewed acceptance. This article is a dated engineering assessment and evidence record. Its rough implementation estimate is independent of the Project's task counts.

    Estimated implementation: approximately 20%¶

    The completion target is a Windows GUI that converts one verified commercial 3DS revision into a WUP, followed by successful Wii U installation, Menu launch, interactive gameplay, audio, and save/reload. Clean Windows operation, rebuild/save continuity, stability, and measured useful performance are part of acceptance. Broad game compatibility is a later goal.

    About 20% is a rough engineering judgment about implementation toward that target. It is not calculated from tests, commits, version numbers, or subsystem counts. The remaining work includes large, uncertain areas, so this estimate does not predict a release date or mean that 80% of the time remains.

    The earlier estimate was roughly 15% at v0.12. Subsequent work added normal compiler-built homebrew execution, guest thread/context support, standard input and CPU-framebuffer applications, private filesystem save/reload, and standalone application lifecycle support. These advance a reusable runtime needed by the injector. They do not yet demonstrate commercial game execution.

    Full milestone acceptance: 0 of 7. This separate measure tracks complete requirements and required hardware evidence. Partial implementation can exist while every full acceptance checkbox remains open. See the milestone checklist for each verified portion and missing gate.

    What supports the estimate¶

    Area Verified implementation Limits for the finished product
    Host preparation Container inspection, optional local key/seed import and decryption, executable loading, private intake, external code generation, static builds, original metadata/artwork staging Original encrypted execution fixture passes; no complete commercial conversion, actual user-key import or clean Windows execution
    CPU and shared runtime Bounded ARM/Thumb/VFP support, checked AOT boundary, memory, eight single-core guest thread contexts, scoped services Incomplete CPU/HLE coverage; actual game and Wii U timing requirements unknown
    Homebrew execution Eight original normal-CRT/libctru applications, input/exact CPU-written frames, save/reload, standalone lifecycle and read-only RomFS assets Desktop/sanitizer/emulated PPC checks plus physical original fresh-launch save, embedded/SD assets and GX results; broader runtime acceptance remains open
    Packaging Original encrypted writer and independent decrypt/hash/FST/file verification, including real diagnostic RPX payloads Synthetic credentials; no installer acceptance or retained installable package
    Wii U platform Named TXT read-back, fresh-launch save reload, current pictures/Minus return and earlier controls evidence Launch-music regression, exact platform versions, recovery and installed-WUP acceptance remain open

    v0.14.6 passes 184 Python tests and fourteen C suites normally and with ASan/UBSan, including 1,892 FS and 574 report/guide assertions in each mode. Fourteen external AOT probes pass 28 compile/execute checks; 944 independent ARM1176 cases verify the scoped CPU additions. The new RomFS program passes normally, under sanitizers and on emulated big-endian PowerPC with zero fallback. The compiled save/interactive regressions and guarded/live-input replays pass. These are supporting checks, not a measurement of product completion.

    Current reports are under artifacts/reports/console-results-v0146/; the five-app kit and matching source are under artifacts/delivery/console-results-0.14.6/. Private uploaded logs/snapshots are excluded. STATUS.md records validation and the remaining gates. These local artifacts are not a published playable-game release.

    Largest unfinished work¶

    • PICA-to-GX2 renderer: actual game draws, shaders, textures, transfers, and coherency. Displaying CPU-written pixels does not implement this renderer.
    • Commercial runtime integration: Retail asset integration, required services/modules, guest DSP/audio, retail saves, and any CPU behavior exercised by the first game.
    • Selected-title proof: exact Mario revision analysis, boot, menu, gameplay, audio, save/reload, stability, and useful Wii U performance.
    • Finished injection engine: commercial end-to-end orchestration, caching, cancellation/rebuild behavior, native Windows execution, and real WUP installation.
    • Windows GUI: the specified UWUVCI-style workflow is designed but not implemented. Its Inject action will use the proven conversion engine.

    Evidence and inputs still needed¶

    The supplied Mario CIA has not been inspected: it exceeds the attachment tool's 32 MiB transfer limit. The CIA intake helper can export a small private executable view for revision and code analysis when the user's computer is available. An encrypted executable can now be prepared locally with the new optional decryption stage, using locally obtained material. Real console export and native Windows acceptance remain pending. That export excludes game assets; commercial asset integration will require access to those separately.

    The native guide and later Minus exit have user-provided console evidence. The user now reports Native/Guarded/Compiled completed without errors on 0.14.5. No new logs were saved; supplied logs have older build headers. Save failed, though a valid two-record visit-1 snapshot was received. v0.14.6 supplies an independent named TXT result with closed-file read-back and portable save publication/rollback/recovery. The exact prior console failure causes remain unconfirmed. The follow-up requests Save, then a quick original RomFS test, with no long native/input repetition.

    Actual WUP installation also needs the documented console environment and local packaging prerequisites. Native Windows tests remain pending.

    Missing inputs block those acceptance checks and title-specific decisions. Further reusable runtime work remains possible; it does not substitute for the missing evidence. Reassess progress after title boot/rendering, physical diagnostic tests, successful installation, and GUI-driven conversion provide new evidence. The next steps are maintained in current-roadblock.md.

    v0.15.0 advances the same approximately-20% foundation: local encrypted main-content preparation and support-file import have original fixture/known-vector checks and an actual AOT/RPX/WUHB pipeline proof. The reported U.S. latest-firmware/Aroma/ WUP Installer GX2 setup and earlier successes allow continued independent work; exact versions/hard logs remain pending. Commercial rendering/runtime, installed WUP gameplay and GUI proof still dominate remaining work, so no full acceptance gate or percentage increase follows from the decryption increment.

    v0.16.0 adds full canonical RomFS IVFC/metadata verification, private asset blob preparation, a SHA-256 checked file provider and all 14 base texture formats. These advance reusable M3/M4/M6 foundations while the user is away. They do not establish game rendering, Mario gameplay, Wii U file I/O acceptance or installed WUP behavior. The approximately-20% estimate and 0/7 full gates remain unchanged. Current validation/delivery: artifacts/reports/assets-textures-v016/ and artifacts/delivery/assets-textures-0.16.0/.

    v0.17.0 adds standard CPU-backed GX queue operations and a stock-libctru transfer application with exact frame checks. GitHub now exposes seven tracked milestone issues, CI/artifacts, review templates and agent guidance. These improve shared runtime foundations and development visibility. They do not supply the missing PICA draws, actual Mario/console/Windows/installed-WUP/GUI acceptance, so the approximately-20% estimate and 0/7 full gates remain unchanged.

    v0.18.0 adds a bounded PICA command front end, transactional raw viewport/scissor configuration and standard queue/P3D completion, verified by original pinned libctru command construction and a compiled guest. Draw/shader/GX2 scene work and console acceptance remain open, so the rough estimate remains 20% and 0/7 full gates. The owner supplied Project #2; automated population still requires Projects access, and the tool cannot create a duplicate after an access failure.

    v0.20.0 records reviewed physical TXT collection, original save fresh-launch reload, embedded/SD assets and GX transfer/configuration evidence. The looping launch music remains an open regression with a short Audio Check/GX handoff. Project #2 is populated through Actions; its task fields remain authoritative. These scoped successes do not accept a full gate or materially change the approximately-20% implementation estimate.
